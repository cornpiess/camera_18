# Camera18 高画质采集架构

2026-10-27 用户批准。目标：苹果公开能力提供干净、清楚的最终底片，Camera18只承担相机风格。用户只选风格、构图、主动调整真实光圈。

成像层v5升级见[统一相机模拟技术方案](camera-simulation-plan.md)及ARCHITECTURE.md；本文件的采集、光圈、保存与试拍契约继续有效。ProRAW目前仅用于离线对比。

## 固定产品策略

| 事项 | 决策 |
|---|---|
| 采集 | `.photo`；输出与单次均`.quality`；HEIF优先、JPEG回退 |
| 尺寸 | 有读取权限且支持Deferred时请求24MP；否则优先12MP，实际由系统决定；不默认最大像素 |
| 镜头 | 优先虚拟后置多摄；JS焦段坐标映射到设备主摄切换倍率；单摄有物理回退 |
| 光圈 | 切相机自动应用推荐真实光圈，用户可继续调整；推荐/主动光圈控制约束物理主摄，快门/ISO自动，ORIG保持当前光圈 |
| 响应 | ZSL/Responsive按支持启用；Fast Capture Prioritization关闭；设置预热 |
| 原图 | 成片曝光/光圈EXIF保留，不把预览值写成照片事实；ORIG不渲染、不重编码 |
| 颜色 | 当前统一sRGB风格合同，原始HDR底片保留；风格结果SDR，不复制失效增益图 |

## 三个职责

- CameraEngineModule：会话/能力/镜头/曝光收据，不处理照片像素和PhotoKit事务。
- CameraProfileRenderer：唯一风格渲染器，复用共享GPU context；最终任务用固定私有缓存命名空间，防止后续配方变化污染快门快照，也避免每张照片永久增加缓存。
- CameraPhotoStore：串行管理持久任务、Photos原始资产、最终照片获取、渲染与同资产编辑。

## 照片生命周期

1. 快门冻结配方及诊断数据。原生UUID作为磁盘任务ID；JS captureID只作结果关联，绝不直接参与路径。
2. `didCapturePhotoFor`结束快门promise。源照片或代理回调将数据和任务记录原子落盘。
3. 延迟代理以`.photoProxy`尽快提交PhotoKit。创建事务提交前记录资产ID；确认失败才清空ID以便下次恢复，状态不明确时不重复创建。
4. `requestContentEditingInput`获得最终Apple底片。禁止拿代理渲染；ORIG直接复制最终原图供App使用。
5. 其他风格经过共享渲染器，完整分辨率输出HEIC（PhotoKit旧接口回退JPEG）。通过`PHContentEditingOutput`更新同一资产，保存配方/renderer版本/任务ID作为adjustmentData。相册里一张照片，原始资源可撤销。
6. 最终风格文件先保存在任务目录，随后提交Photos编辑，避免Photos临时编辑URL清理导致丢图。重启发现同任务编辑已提交时，只交付已有最终文件，不重复套滤镜。
7. 成功后持久化最新全尺寸照片、缩略图和完成outbox，再清理任务并发事件；JS结算试拍成功才ACK，未确认结果在下次恢复重放。失败保留源与错误，属于非终态；保留试拍预留直到成功或用户明确结束。启动/前台恢复只尝试一次，不循环重试。外部编辑过的照片不自动覆盖。
8. 最近照片按曝光时间选取，恢复旧照片不倒退最新入口。全尺寸文件跨启动保留，缩略图不作为查看器原图；查看器支持双指缩放。

## 权限与设备回退

首次使用申请照片readWrite，limited也可处理本App创建的可访问资产。拒绝读取时关闭Deferred并请求直接交付的质量底片，不让用户选择画质开关。

只有addOnly权限时，本地完成风格后创建一个相册资产，原始底片和配方留在Application Support/Camera18Originals。此路径不支持在系统相册撤销风格，且保留的原始文件会占本地存储；它不是完整PhotoKit非破坏性编辑的等价替代。ORIG仍直接保存原始字节。拒绝保存权限时任务留本地，下次恢复可继续。

采集最多3个在途delegate；活动持久任务达到8个时暂停接收新拍摄（失败等待任务不占活动名额）。仅一个最终照片任务同时执行，原生文件与像素处理不进入JS线程。用有限UIApplication后台任务争取处理时间，到期撤销当前尝试、保留日志；不承诺被挂起或杀进程后持续执行，重开后恢复。

## 统一拍摄状态与恢复入口

原生状态：不可用、曝光中、光学调整中、光圈未到位、处理繁忙、可拍。JS保留按操作来源合并的光学准备状态；屏幕与硬件快门共用拍摄入口，原生再次校验。光圈硬件确认与3秒兜底均回读，不达目标不能算成功；禁拍直到重试成功。焦段input/zoom失败一并回滚，旧事务不得覆盖新选择；回滚失败要求重建会话。

照片状态入口显示正在完成/等待重试，支持一次性重试、系统设置、可解码原图导出和本地原图管理。直接底片失败可显式保留原图并结束风格处理，释放未完成试拍；代理不能当成最终原图导出。清理归档原图有二次确认，不触及Photos资产；原图留存不会自动清理，会占本地空间。

Keychain持久化captureID与Profile绑定的预留/已提交收据。可恢复失败不释放预留，成功仅提交一次；结果outbox先落盘再发事件，JS在Keychain提交/回滚成功后ACK。重复重放、免费/PRO混拍不消费其他预留；只清理上一进程无任务或结果的孤立预留。不改变现有三张试拍政策。

## 光圈与预览边界

推荐光圈与色彩共同构成相机性格：切相机自动应用推荐真实光圈，返回主摄恢复相机推荐值，用户可继续调整。降噪优化必须在此设定下进行，不能取消或偷偷改大光圈；固定镜头不伪造。不为强制手动参数降级到speed。苹果融合仍有自己的曝光决策，最终EXIF是事实，预览光圈只是诊断数据，硬件组合不能靠静态检查证明。

虚拟设备用于自动选镜，不代表获得系统相机所有私有功能。没有承诺Night mode、Photographic Styles或所有镜头组合与系统相机完全一致。预览与成片共用风格定义，不承诺多帧计算摄影结果逐像素一致。

## 工程验证

本地：typecheck、lint、Expo doctor、离线iOS bundle、Swift结构/语法树检查、LUT/配方回归、拍摄ID乱序/重复/恢复测试、密钥扫描。

设备/CI工程验收：

- iOS原生编译（含无测试标志生产配置）。
- 全读取/limited/addOnly/拒绝/撤销权限路径；新建资产在limited下的可访问性。
- 有/无延迟代理、最终24MP或系统降级尺寸、ORIG字节保持、风格分辨率不变。
- 每次快门一个资产、撤销编辑能恢复原图；在代理保存前后、最终化中、编辑提交前后杀进程，恢复不产生重复资产或重复风格。
- 旧设备HEIF/JPEG编码回退，固定镜头/虚拟多摄/主动主摄光圈切换，镜头切换失败回滚。
- 连续拍摄、任务乱序、后台挂起与恢复、存储耗尽、系统压力下内存；排队不应导致JS线程阻塞。
- 同场景自动化采集ORIG与系统相机参考，记录实际ISO/快门/镜头/尺寸，检查噪点和纹理；这是工程验收，不要求用户反复切开关排查。

本地门槛包括doctor20/20、iOS离线导出（当前757modules）、ID结算与颜色/校准回归；Swift语法树检查不代替SDK编译。已有ApertureBar hooks警告单独披露。

静态检查不能证明实际画质改善或苹果处理分支。当前环境无Xcode/iPhone，原生编译与以上设备矩阵尚未执行；构建仅按用户明确请求触发。
